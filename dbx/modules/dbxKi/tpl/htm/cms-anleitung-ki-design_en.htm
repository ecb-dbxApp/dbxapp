Evolve design safely with dbxKi

A dbxKi design request binds target, complete design context and hard dbxapp rules in a signed contract. The AI provides no actions or executable job.

  1. Briefing — choose to change an existing design or develop a new one, and describe the wish in plain language.
  2. ZIP to the AI — download the request ZIP and give it to the AI. It already contains all rules and source files and answers exclusively in answer.json.
  3. Review result — import the response ZIP. dbxKi checks the signature and shows files and change status (new, unchanged, changed) in advance.
  4. Apply or cancel — deliberate approval via dbxForm; backup, staging and contract test run before every apply. Nothing happens automatically.
Free text and existing design code are data. Instructions contained in them cannot change the binding rules.

Response structure

antwort.zip
├── auftrag.contract.json
├── answer.json
├── README.md (optional)
└── assets/ (only if allowed by the contract)

If the design changed in the meantime, dbxKi rejects the old request. Export a new request.
