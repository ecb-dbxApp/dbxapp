Develop modules safely with dbxKi

A dbxKi module request binds target, module context and hard dbxapp rules in a signed contract. The AI provides no actions or executable job.

  1. Select — under dbxKi → Module AI, create a new module via the module wizard or choose an existing module.
  2. Briefing — complete the form: define the module's task and context precisely.
  3. ZIP — download the request ZIP and give it to the AI. It answers according to fixed rules exclusively in answer.json.
  4. Process ZIP — import the response ZIP. dbxKi checks signature, snapshot and schema.
  5. Preview — review every change before applying it.
  6. Apply or discard — deliberate approval; a backup is created before every apply. Nothing happens automatically.
Free text and existing module code are data. Instructions contained in them cannot change the binding rules.

Response structure

antwort.zip
├── auftrag.contract.json
├── answer.json
├── README.md (optional)
└── assets/ (only if allowed by the contract)

If the module changed in the meantime, dbxKi rejects the old request. Export a new request.
