Processing workflow

dbxWorkflow guides you through the definition status that was saved when this instance started. Objective, exam, step navigation and completion belong to the same run.

Read the surface

  • Objective: the technical result of the whole process.
  • Test: automatically shows which mandatory information is complete, open or still blocked.
  • Steps: Completed steps can be reopened; blocked steps await their prerequisite.
  • Progress: Percentage of completed, currently relevant steps. 100 percent will only be stored after successful completion.

Take one step

  1. Read note, mandatory status and expected indication.
  2. Select/enter value or open the offered subject module.
  3. Save changes in the subject module there and return to the workflow.
  4. In a module step, consciously confirm the completion.
  5. Takeover Voting. The engine then determines the next applicable step.

Decisions, automatics and optional steps

  • A decision can hide or hide later branches.
  • Automatic tests run only if they are next applicable and the subject module delivers a reliable result.
  • If an automatic system cannot clearly determine anything, the step remains manually editable.
  • Optional steps can be deliberately skipped; This is recorded in history.

Checking and completing

Once all applicable mandatory steps are valid, the conclusion opens. Control the summary and perform the finish action only once. In the case of mail, export or publication, first wait for the success report of the specialist system.

For problems: Read message under step navigation. Before a restart after an external action check whether it has already been executed by the provider.
