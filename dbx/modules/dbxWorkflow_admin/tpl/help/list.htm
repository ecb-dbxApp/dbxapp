Wofür ist diese Übersicht?

Hier verwalten Sie die Definitionen, die das Modul dbxWorkflow später ausführt. dbxWorkflow_admin legt Ziel, Schritte, Prüfungen und optionale Modul-Anbindungen fest; dbxWorkflow erzeugt daraus für jeden Start eine eigene Instanz.

Definition in dbxWorkflow_admin → aktivieren und testen → Start in dbxWorkflow → Instanz mit Definitions-Snapshot → Schritte bearbeiten → prüfen und abschließen

Typischer Ablauf

  1. Neuer Workflow: Ziel und stabilen Workflow Key festlegen.
  2. Schritte: Eingaben, Aktionen, Prüfungen und Entscheidungen in die richtige Reihenfolge bringen.
  3. Test: Definition zunächst inaktiv speichern, kontrollieren und danach aktivieren.
  4. Starten: Über die Start-Aktion einen neuen Durchlauf in dbxWorkflow öffnen.
  5. Überwachen: Laufende und abgeschlossene Durchläufe unter Workflow Instanzen prüfen.

Wichtig

  • Nur aktive Definitionen können neu gestartet werden.
  • Ein unbekannter oder deaktivierter Workflow Key wird nicht durch einen Demo-Ablauf ersetzt.
  • Beim Start speichert die Instanz einen Snapshot. Spätere Änderungen gelten deshalb erst für neue Durchläufe.
  • Die mitgelieferten Beispiele werden bei der Installation einmalig angelegt und können danach wie normale Definitionen bearbeitet werden.
Beispiel: project_offer in der Liste aktivieren → Starten → dbxWorkflow legt eine neue Instanz an und zeigt den ersten anwendbaren Schritt.
