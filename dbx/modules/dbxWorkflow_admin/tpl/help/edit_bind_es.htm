Proceso de unión

Binding describe la conexión técnica entre una definición de flujo de trabajo y un módulo de materia existente. Se almacena como JSON y más modul|bind_key referenciado.

Empieza con el generador

  1. Introduzca el nombre del módulo.
  2. Seleccione un DD del módulo.
  3. Cree el marco básico y luego pruebe el JSON.
  4. Guardar clave única, título comprensible y estado activo.

Principales esferas

registro → Fach-DD y necesidad con el ID de conjunto de datos necesita[] → Selección, opciones de campo, preocupación y contexto por paso end[]→ permitió el cambio de tema y la acción opcional de seguimiento
Ejemplo simplificado: 
{
  "record": {"dd": "dbxContact|contactRequest", "id_need": "contact_request"},
  "needs": {
    "contact_request": {"type": "dd_select", "label": "{subject}"},
    "status": {"type": "dd_field_options", "field": "status"}
  },
  "finish": {
    "type": "dd_update",
    "map": {"status": "status"}
  }
}

Compruebe antes de la activación

  • ¿Existe DD, nombres de campo y plantillas?
  • Shows id_need ¿Un paso de la definición de flujo de trabajo?
  • ¿Se consideran suficientemente estrictos los filtros de selección y los derechos de configuración de datos?
  • Modificado finish ¿Sólo los campos designados?
  • ¿El correo o una acción externa sólo se ejecuta después de un cambio exitoso?
