Workflow im Designer erstellen

Der visuelle Designer beschreibt ein fachliches Ziel und alles, was dafür benötigt wird. Die technische JSON-Definition wird beim Speichern automatisch erzeugt; die technische Vorschau ist nur zur Kontrolle gedacht.

1. Ziel festlegen

  • Workflow Key: stabiler technischer Schlüssel, zum Beispiel project_offer. Nach produktiven Starts nicht mehr umbenennen.
  • Name: verständlicher Titel des Ablaufs.
  • Ziel: konkretes Ergebnis, das nach dem Abschluss vorliegen soll.
  • Beschreibung: kurz erklären, wann der Workflow verwendet wird.
  • Aktiv: nur aktivierte Definitionen dürfen neu gestartet werden.

2. Schritte aufbauen

Baustein anklicken oder in den Ablauf ziehen, Details öffnen und anschließend per Griff in die richtige Reihenfolge bringen.

  • Eingabe: Wert erfassen, auswählen oder neu anlegen.
  • Aktion: ein vorhandenes Fachformular öffnen und die Erledigung bestätigen.
  • Prüfung: Daten kontrollieren; mit Automatisch prüfen nur dann selbstständig, wenn das Fachmodul einen sicheren Wert liefern kann.
  • Entscheidung: mindestens zwei Ergebnisse definieren, auf die spätere Schritte verzweigen können.

3. Pflicht, Bearbeitung und Verzweigung

  1. Für jeden Schritt eine eindeutige Bezeichnung und einen eindeutigen internen Schlüssel vergeben.
  2. Erlaubte Bearbeitungen wählen: Formular, Auswahl, Neuanlage und/oder Modulformular.
  3. Pflichtschritte müssen einen gültigen Wert liefern; optionale Schritte können bewusst übersprungen werden.
  4. Für einen Zweig unter Voraussetzung einen früheren Schritt und optional unter Nur bei Ergebnis dessen Wert angeben.
  5. Auswahlwerte zeilenweise als wert=Beschriftung eintragen.
Freigabe (key: approval) ├─ approved → Auftrag ausführen └─ changes → Rückfrage bearbeiten

4. Modul anbinden und testen

Um DD-Auswahlen, Fachformulare oder Finish-Aktionen zu verwenden, unter Erweiterte Angaben eine Referenz wie dbxContact|contact_reply eintragen. Das zugehörige Binding wird separat unter Modul-Bindings gepflegt.

  1. Speichern und alle Designer-Meldungen beheben.
  2. Definition aktivieren.
  3. Aus der Workflow-Liste einen neuen Testdurchlauf starten.
  4. Pflichtwerte, Verzweigungen, Modulaktionen und Abschluss vollständig testen.

Hinweis: Bereits laufende Instanzen behalten den Definitionsstand ihres Starts. Eine Korrektur im Designer wirkt auf den nächsten neu gestarteten Durchlauf.
