Tutorial · Installation

dbxapp Schritt für Schritt installieren

In diesem Tutorial richten Sie eine neue dbxapp-Installation kontrolliert ein. Nach jedem Abschnitt prüfen Sie ein sichtbares Ergebnis, bevor Sie fortfahren.

Ergebnis Am Ende können Sie sich mit einem persönlichen Administrator-Passwort anmelden und erhalten einen bestandenen Schnelltest.

1. Vorbereitung

Systemvoraussetzungen prüfen

Stellen Sie vor dem Kopieren der Dateien sicher, dass der Zielserver die Pflichtvoraussetzungen erfüllt.

PrüfungErforderlicher ZustandKontrolle
PHPVersion 8.2 oder neuerphp -v oder Serverübersicht
ErweiterungenSession, PDO, JSON, Filter, Hash und OpenSSLphp -m
Autoloaddbx/vendor/autoload.php vorhandenDatei im Paket kontrollieren
Schreibrechtefiles, tmp und lokale Konfiguration beschreibbarSystemprüfung im Assistenten
HTTPSFür Produktion aktivAdresse beginnt mit https://

Sicherung und Zielverzeichnis vorbereiten

  1. Bei einer bestehenden Umgebung zuerst Dateien, lokale Konfiguration und alle Datenbanken sichern.
  2. Für eine Neuinstallation ein leeres, eigenes Webverzeichnis verwenden.
  3. Ein persönliches Admin-Passwort mit mindestens zwölf Zeichen vorbereiten.

2. Dateien bereitstellen

Release entpacken

  1. Paket kopierenDas vollständige Release in das Zielverzeichnis entpacken. Keine Dateien einer älteren Version darüberkopieren.
  2. Document Root setzenDer Webserver zeigt auf das Verzeichnis, in dem sich index.php befindet.
  3. Rechte begrenzenNur Laufzeitverzeichnisse und lokale Konfiguration beschreibbar machen; Quellcode bleibt im Betrieb lesbar.
  4. Startseite öffnenDie neue Installation leitet automatisch zum Installationsassistenten weiter.

Kontrollpunkt

Der Assistent zeigt Schritt 1 „Systemprüfung“. Eine normale Website oder eine leere Seite wäre an dieser Stelle nicht korrekt.

3. Assistent ausfüllen

Schritt 1 bis 3: System, Website und Datenspeicher

  1. Alle roten Pflichtfehler in der Systemprüfung beheben.
  2. Website-Titel, Markenname, Standardsprache, Zeitzone und Designs festlegen.
  3. DB3 für den direkten Einstieg oder ein geprüftes PDO-Ziel für einen zentralen Datenbankserver auswählen.

Schritt 4 bis 6: Daten, Administration und E-Mail

  1. Strukturen erst nach erfolgreicher Datenbankverbindung anlegen. Eine Datenübertragung nur nach zusätzlicher Bestätigung starten.
  2. Für admin das vorbereitete persönliche Passwort zweimal identisch eingeben.
  3. Für den ersten Test den Mailmodus internal verwenden oder eine vollständig geprüfte SMTP-Konfiguration hinterlegen.

Schritt 7: Zusammenfassung und Abschluss

Prüfen Sie Website, Sprache, Zeitzone, Datenbankmodus, Administrator und Mailmodus. Geheimnisse dürfen in der Zusammenfassung nicht im Klartext erscheinen. Schließen Sie die Installation erst danach ab.

4. Installation abnehmen

Anmelden und Schnelltest starten

  1. AnmeldenMit admin und dem in Schritt 5 vergebenen Passwort anmelden.
  2. SelfTest öffnenIm Adminmenü System → System-Selbsttest wählen.
  3. Schnelltest ausführenDer Lauf muss ohne Fehler enden. Details zu übersprungenen optionalen Werkzeugen bewusst bewerten.
  4. Kompletttest planenVor der produktiven Freigabe zusätzlich den vollständigen Testkatalog ausführen.

Abnahmeprotokoll

KontrolleBestanden, wenn …
AnmeldungDas persönliche Admin-Passwort funktioniert und kein Standardpasswort ist aktiv.
KonfigurationDesign, Sprache, Zeitzone, Mailmodus und Datenbankbindungen stimmen.
SchnelltestAlle Pflichtprüfungen sind grün und der Lauf ist abgeschlossen.
BackupKonfiguration, Dateien und gebundene Datenbanken sind extern gesichert.

5. Typische Fehler beheben

Der Assistent startet immer wieder

Schreibrechte und Inhalt von dbx/modules/dbx/cfg/config.local.php prüfen. Der erfolgreiche Abschluss speichert dort lokal install = 0.

Die Datenbankverbindung schlägt fehl

PDO-Treiber, Host, Port, Datenbankname und Benutzerrechte kontrollieren. Ohne erfolgreiche Verbindung keine Schema- oder Datenübertragung starten.

Es erscheint eine leere Seite

PHP-Version, Pflichtmodule, vendor/autoload.php, Webserver-Protokoll und files/dbxError.log prüfen.
