Welcome to Content CMS

The Content CMS is the central interface for website content in dbXapp. Here you can manage Folders, Pages, Media, Rights and, for several languages, the Translations.

Entry: ?dbx_modul=dbxContent_admin&dbx_run1=cms

Further selection and dialog fields

  • Tree search: Snag the visible pages and folders.
  • Media advertisement: Filters associated media by All, Gallery, Hero, Text or Shop.
  • Media folder/upload destination: determines from which media folder is displayed or uploaded to which folder.
  • File selection: Select one or more local files for the upload.
  • External video URL: records an supported video URL, for example YouTube.
  • Activate the target language: specifies in the translation dialog which language versions are created or updated.
  • Entire subtree incl. Pages: For folders also covers all subfolders and pages.

Basic concepts

  • Folders — structure the tree (like directories). Has Reading Rights and optional Hero.
  • page — actual content with title, text, permalink and media.
  • Permalink — URL path of the page (e.g. leistungen/beratung).
  • Master language – leading language (usually DE). Changes here control Auto-Sync.
  • Language version — same content in another language, linked to internal ID.

Creating a new page

  1. In the tree the Destination folder Click.
  2. Button New page (gruen, file icon).
  3. Edit title and text in the editor.
  4. Storage (disc) or Strg+S).
  5. In Master Language: Dialogue Translate into other languages opens — even when saving existing pages, if EN/ES is still missing.
Example: Folder “Services” → New page → Title “Consultation” → Write text → Save → Enable EN version in dialogue → Take over. EN-page is first Inactive.

Duplicate existing page

  1. In the tree to be copied page Click.
  2. If "Unstored" appears, first Storage.
  3. To the right of the green button "New Page" Duplicate page (Two files) click.
  4. The new page is created in the same folder and immediately opened in the editor.

The copy receives a new page ID, a new language link and a new sorting position. Title, status, SEO fields, content, hero/gallery settings and media will be preserved. The permalink is automatically ...-kopie set; It already exists, follows ...-kopie-2 etc.

Media: The files are not physically multiplied. For Hero, gallery and other areas create their own media_usage-Assignments to the new page; Inline media are reassigned from the copied editor content.

Create new folders

  1. Choose parent folders in the tree (or root).
  2. New folders in the tree context or via the folder view.
  3. Name, Parent and Reading Rights Set → Save.
  4. As with pages: commission dialogue for other languages.

Editing page or folder

  1. Click entry in the tree.
  2. Adjust meta fields (title, permalink, status, template).
  3. Change content in the editor — Modules by placeholder [modul=...].
  4. Assign media to the right (hero, gallery, in text).
  5. storage. The saved point in the header shows unstored changes.

Media

  • Hero — Big head image at the top of the page.
  • Gallery — Picture gallery under the content.
  • In text — Pictures/videos inline in the editor.
  • The media are in Media browsers selected; Files remain in stock even if you remove the link.
Tip: After storing in the master language, media connections are taken over in auto-sync languages.

Multilingualism — This is how it works

dbXapp separates content per language into its own tables ()content_de, content_en, ... They are bound to lng_uid.

Store master (DE*) │ ├─► Slave with Auto-Sync → is automatically updated (text + structure + media) │ └─► Slave with manual → remains unaffected (fork)

Language tabs and badges in the tree

  • DE*, EN, ... — Language tabs change the editing language.
  • Badges at the tree entry: master, auto, manual or missing.
  • Master (*) — only here: Transfer, activate auto-sync, delete multilingually.

Transferred to other languages (provision)

  1. The page or folder in the Master language Voting.
  2. Button Translating (Language icon) in the header.
  3. Dialogue: activate target languages, check texts and adjust them if necessary.
  4. Takeover — new language versions are created (pages: inactive).

In Folders Additional: Checkbox Entire subtree incl. Pages — submits all subfolders and pages in one step (folder first, then pages).

Auto-Sync in master storage

If you have a page or folder in the master language UpdateAll connected slaves with status auto Synchronized in the background. You will see a message like “2 language version(s) synchronized”.

  • Texts are translated (depending on the provider).
  • Structure (template, hero settings, sorting) is taken over.
  • Status active/inactive The slave page is retained.

Fork — Manual deviation

Save them in one Non-master language, the connection is separated ()manual) The message reads: Language connection separately (manually).

From then on, the master no longer automatically adopts this language.

Activate Auto-Sync again

  1. Select the page/folder in the master language.
  2. Button Auto-Sync (Link icon) in the header.
  3. Asserting – all connected slaves get back auto.
  4. Next master save syncs again (rewrites slave content).

Deletion

Slave language: Simple confirmation — only this language version is deleted.

Master with several languages: Dialogue with checkboxes per language.

  • auto-Versions are preset.
  • manual-Versions not - deliberately tick if desired.
  • Folder can only be deleted if there are no subfolders and no pages (checked per language).

Preview and publication

  • Preview (eye icon) — opens the page in the frontend.
  • Status Active/Inactive — only active pages are publicly accessible.
  • New slave sites start as Inactive — only set to active after verification.

Cache

After saving, the guest full page cache is automatically invalidated. For Gaeste, it stores the complete final output of valid permalink calls including design, menues and modules. Registered users remain dynamic. If changes are not visible live:

  1. Admin → check page cache / empty.
  2. Call up the page again (hard reload in the browser).

Keystrokes

  • Strg + S — Save (page or folder)

Frequent questions

Why is EN missing in the tree?
Page was created only in DE – Run commission dialogue or use the translation button.

Why is EN no longer updated?
Slave was stored manually (fork). Use Auto-Sync button or re-edit EN.

Note about folders in the commission dialog?
Missing folders in EN/ES are automatically created from the master structure (including parent folders) when transferred. In the dialog, a hint appears instead of an error.

Does translation not work?
Provider and API key in Modul-Config check → Read SysMsg.

Where can I find technical details?
Developer documentary: 04_DBXApp_CMS_Mehrsprachigkeit.md in the project.

Typical workflow (multilingual website)

1. Create folder structure in DE 2. Write pages in DE + Media 3. Commission → EN (and other languages) 4. EN test → Status “Active” 5. Changes only in DE* → Auto-Sync maintains EN 6. Special EN texts: Edit in EN (Fork)
Example homepage: DE page “Home” with Hero → Commission EN → Adapt title “Home” / “Start” → Activate EN → Permalink check.
