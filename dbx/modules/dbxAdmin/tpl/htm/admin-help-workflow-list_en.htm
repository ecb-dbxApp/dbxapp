What is this overview for?

Here you manage the definitions that the module dbxWorkflow later on. dbxWorkflow_admin specifies the objective, steps, tests and optional module connections; dbxWorkflow generates a separate instance for each start.

Definition in dbxWorkflow_admin Activate and test → Starting in dbxWorkflow Instance with Definition Snapshot → Processing steps Examine and Complete

Typical procedure

  1. New workflow: Set goal and stable workflow key.
  2. Steps: Put inputs, actions, tests and decisions in the right order.
  3. Test: First inactively save, control and then activate definition.
  4. Starting: About the start action a new pass in dbxWorkflow open.
  5. Monitoring: Continuous and closed runs under Workflow instances check.

Important

  • Only active definitions can be restarted.
  • An unknown or deactivated workflow key is not replaced by a demo expiration.
  • At startup, the instance saves a snapshot. Subsequent changes therefore only apply to new runs.
  • The included examples are created once during installation and can then be edited like normal definitions.
