Languages in dbXapp — Overview

dbXapp distinguishes two levels:

  • System languages — which languages are available on the website and in the admin (e.g. German, English, Spanish).
  • Content Languages in CMS Every page and every folder exists Per language as a separate data set, but the versions are linked.

This help explains both: the settings on this Config page and the daily work in the content CMS.

Working in Content CMS

Entry CMS: ?dbx_modul=dbxContent_admin&dbx_run1=cms

  • Language tabs above (DE*, EN, ES) — change the editing language. The star shows the master language.
  • New page/folder in Master — after saving, the dialog appears if necessary Translate into other languages.
  • Button "Translate" (Language icon) — creates missing language versions or updates the preview before transferring.
  • Button "Auto-Sync" (Link icon, master only) — returns separate languages to automatic execution.

Transferred to other languages (provision)

  1. The page or folder in the Master language Voting.
  2. Open dialog (after saving or via translation button).
  3. Tick target languages, check texts — API providers generate advances.
  4. Takeover — New versions are created. Pages start inactive, so that you can check before publication.

In Folders You can optionally use the The entire subtree incl. Pages also transmitted. Missing folders in target languages are automatically recreated from the master structure.

Auto-Sync — Save Master

If you save in the master language, all linked languages with status auto updated in the background:

  • Texts (translated or copied depending on the provider)
  • Structure, template settings, permalink base
  • Media connections (hero, gallery, pictures in the text)

The Active/Inactive status the target language is preserved – an inactive EN page is not suddenly switched live by master sync.

Fork — If a language is to remain unique

Save them in one Non-master language, the linkage is separated ()manual / Fork. Message: Language connection separately (manually).

From then on, the master no longer automatically adopts this language. This makes sense for adapted marketing texts or other permalinks.

To join again: in the master language Auto-Sync Activate — the next master save then rewrites the slave content.

In case of API errors, the original text is taken over. In addition, a note appears in the CMS and an entry under Admin by SysMsg (About:) dbxContentTranslate).

Which provider for whom?

  • Customer installation (standard): copy — always works without cost and without external service.
  • Small website with auto translation: deepl with DeepL API Free (about 500,000 characters per month, 0 EUR).
  • Larger sites / many texts: DeepL API Pro (paid) or manually with copy maintain dialogue.
  • OpenAI: Only if the operator deliberately bears API costs — ChatGPT Plus/Pro is not API access.
  • Google Translate: In dbXapp not installed. Only over custom + own development possible.
Important: ChatGPT in the browser (Plus, Pro, ...) and the OpenAI API are Two separate products. A chat subscription does not provide an API key and no API credits.

Working without API key (standard)

Providers copy Select — leave all fields for API blank. When transferred to other languages, the master text is taken over; You manually adjust the texts in the commission dialog or in the target language. This is the safest option for editorial and customer installations.

Google and other providers

Google Cloud Translation and similar services dbXapp not directly as a provider. Google offers a small free quota for new cloud accounts, after which the use is paid. A connection would only be about the provider custom and one of their own translate.php possible by a developer.

Home page per language

The Home page (master) is the content ID of your home page in the master language (e.g. home page with ID 1).

  • Visitors in the master language see this page as a homepage.
  • In EN/ES, the system searches for the matching linked page (same content, different language).
  • If a language version of the homepage is missing, there is no home page for this language.

Delete in several languages

Delete them from the Master language and there are several language versions, a dialog with checkboxes appears:

  • auto-Versions are preset
  • manualVersions only on request
  • Permalinks are cleaned per language

Media and languages

Media files themselves are Language neutral (one image, one file). They are linked per page and language (hero, gallery, inline in the text). In commission and auto-sync, these links are copied into the target languages – not the file duplicated.

For website visitors

  • The Available languages from this config determine which languages are offered.
  • The selected language controls menu, permalink resolution and the voice-dependent guest full-page cache file.
  • Only Active Pages are publicly visible — check new translations first, then actively set them.

Cache and Live View

After saving, the page cache is usually automatically updated. If changes are missing live:

  1. Admin page cache empty
  2. Reload page in browser with hard reload

Frequent questions

Why is EN missing in the tree?
The page was created only in the master language. Save or “Translate” → execute commission for EN.

Why is EN no longer updated?
EN was stored once manually (fork). Re-activate auto-sync in the master language or consciously maintain EN yourself.

Does translation make mistakes?
Provider and API key on this config page Admin by SysMsg Reading. Until the correction, text is copied. For DeepL: Check free key and empty API URL. In OpenAI: Billing on platform.openai.com Active?

I have ChatGPT Pro — is that enough?
No. ChatGPT Pro is only the chat subscription in the browser. For dbXapp You need a separate API key from platform.openai.com (paid after use) — or you stay with copy DeepL Free.

Is there a free car translation for customers?
copy is always free. DeepL API Free (about 500,000 characters/month) is free, but each customer needs their own account: deepl.com/pro-api.

Can I change the master language?
Technically yes — but concerns CMS logic and homepage. Change only wisely and then check structure/links.

What does the migration notice below mean?
Internal database status for multilingual tables — not relevant for everyday use, only for support/updates.

Typical process (multilingual website)

1. Here: Master Language + Available Languages + Provider Set 2. CMS: Create folders and pages in Master 3. Commission → EN (and other languages) 4. Check target languages, adjust Permalink + text 5. Pages in target languages on “Active” 6. Ongoing care only in Master* → Auto-Sync keeps EN/ES current 7. Special deviations: edit in EN/ES (Fork)
Example: Homepage ID 1 → Provision EN → EN text “Welcome” check → Activate the EN Visitors with EN see the twisted English home page.
